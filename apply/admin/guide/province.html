3. 회차 운영 체크리스트

신청 시작 3~4주 전

  • 지난 회차 명단을 모두 내려받아 보관했는지 확인(7장)
  • 지난 회차 강좌 · 신청자 정리 — 「이 프로그램 전체 초기화」(9장)
  • 지역청 담당자 계정 상태 확인: 퇴직 · 전보자가 있으면 비밀번호 초기화 또는 정지(8장)
  • 지역청에 강좌 등록 기한, 엑셀 양식, 지역청 담당자 매뉴얼 주소 안내

신청 시작 1~2주 전

  • 기본 신청 기간 입력, 필요하면 강좌 공개 시각 입력(5장)
  • 지역청별 강좌 등록 현황 확인 — 강좌 표의 지역 열
  • 강좌명 · 정원 · 최소 개설 인원 · 대상 학년 · 일정 점검. 학년 제한 강좌는 「수강 대상」이 운영 학년도 기준인지와 시작일 확인
  • Supabase 요금제를 Pro로 올림(10장)
  • 학교 · 학생 안내 공문에 수강신청 입구 주소(지역 기간이 다르면 지역별 주소), 강좌 공개일, 신청 기간 기재

강좌 공개일 ~ 신청 기간 중

  • 공개일에 수강신청 입구 칸이 신청 화면으로 연결되는지, 강좌 목록이 보이는지 확인
  • 신청 시작 직후 관리 화면에서 신청 수가 올라가는지 확인(「새로고침」)
  • 문의 대응, 정원 조정, 강제마감(6장)

신청 마감 후

  • 「전체 엑셀」로 전체 명단 내려받기
  • 「폐강 위험」 강좌 확인 → 지역청과 폐강 여부 협의
  • 개설 확정 명단을 지역청 · 학교에 송부
  • Supabase 요금제를 Free로 되돌림

4. 관리 화면과 강좌 관리

강좌 등록 · 엑셀 일괄 등록 · 수정 · 삭제와 학년 제한 규칙은 지역청 매뉴얼 4~6장과 같습니다. 도교육청 계정에서 다른 점은 다음과 같습니다.

  • 위쪽 단추에 가입 승인이 더 있고, 프로그램 탭에 「전체」와 세 프로그램이 모두 보입니다.
  • 등록할 프로그램 탭을 먼저 누른 뒤 + 강좌 등록을 누르면 프로그램이 미리 선택됩니다.
  • 지역은 반드시 「○○교육지원청」 전체 이름으로 적습니다. 약칭으로 적으면 지역청 담당자에게 보이지 않고, 강좌 코드의 지원청 자리에 ZZ가 들어갑니다.
  • 강좌 코드를 직접 입력할 수 있습니다(등록 후에는 바꿀 수 없음).
  • 특정 프로그램 탭을 누르면 빨간 「위험 구역」(9장)이 나타납니다.

강좌 코드 규칙

프로그램 2자 + 학년도 2자 + 운영 기간 1자 + 지원청 2자 + 순번 2자. 예: JR27SCA01 = 지역연계 · 2027학년도 · 여름방학 · 천안 · 1번

구분값
프로그램지역연계 JR · 고교-대학 연계 DC · 꿈키움 DU
운영 기간1학기 1 · 여름방학 S · 2학기 2 · 겨울방학 W. 고르지 않으면 시작일의 달로 정함(3~6월 1, 7~8월 S, 9~12월 2, 1~2월 W)
지원청천안 CA · 공주 GJ · 보령 BR · 아산 AS · 서산 SS · 논산계룡 NG · 당진 DJ · 금산 GS · 부여 BY · 서천 SC · 청양 CY · 홍성 HS · 예산 YS · 태안 TA · 그 외 ZZ

학년도는 3월에 바뀝니다. 2028년 1월 겨울방학 강좌는 2027학년도이므로 27W입니다.

5. 신청 기간 설정

신청 기간은 관리 화면 신청 기간 창에서 프로그램별로 넣습니다. 저장하면 학생 화면과 좌석 선점에 바로 적용됩니다.

  1. 신청 기간을 누르고 창 위쪽 「프로그램」에서 프로그램을 고릅니다.
  2. 첫 줄 「기본 기간 (전체)」에 강좌 공개(선택) · 1차 시작 · 1차 마감을 넣습니다. 2차는 필요할 때만 시작과 마감을 함께 넣습니다.
  3. 저장을 누릅니다.

기본 기간과 지역 기간

지역연계는 기본 기간 아래에 14개 지원청 줄이 있습니다. 학생 화면은 ① 그 지원청의 지역 기간 → ② 없으면 기본 기간 → ③ 둘 다 없으면 신청 불가 순으로 기간을 고릅니다. 지역청 담당자는 자기 지원청 줄만 저장할 수 있고, 도교육청은 모든 줄을 고칠 수 있습니다.

「적용」 표시뜻
설정됨 / 미설정기본 기간이 있음 / 없음
지역 기간그 지원청만의 기간. 기본 기간보다 우선
기본 기간 따름지역 기간이 없어 기본 기간을 씀
미설정 · 신청 불가기본 기간과 지역 기간이 모두 없음

좌석 선점 · 취소는 학생이 고른 지역이 아니라 강좌의 지역 기간으로 판단합니다. 학생 취소는 신청 기간이 끝나면(2차가 있으면 2차 마감 뒤) 막힙니다.

강좌 공개(미리 보기)

「강좌 공개」를 비워 두면 1차 시작 7일 전부터 학생이 강좌 목록을 볼 수 있습니다. 공개 전에는 학생 화면에 공개 일시만 나오고, 공개 후 신청 시작 전에는 목록 · 상세보기만 되고 신청 단추는 눌리지 않습니다. 수강신청 입구 칸도 공개 시각부터 신청 화면으로 연결됩니다.

수강신청 입구는 기본 기간을 따릅니다

입구의 지역연계 칸은 기본 기간(과 그 공개 시각)만 보고 바뀝니다. 기본 기간보다 먼저 여는 지원청은 …/apply/app.html?program=joint_regional&region=천안처럼 지역 주소를 직접 안내해야 합니다.

입력 규칙

  • 시각은 한국 시간입니다. 1차 시작 · 1차 마감은 필수이며 마감이 시작보다 뒤여야 합니다.
  • 강좌 공개는 1차 시작보다 앞이어야 합니다.
  • 2차는 시작과 마감을 함께 넣고, 2차 시작은 1차 마감보다 뒤여야 합니다.
급히 신청을 멈출 때

「1차 마감」(2차가 있으면 「2차 마감」)을 지금보다 이전 시각으로 바꿔 저장하십시오. 학생 화면은 1분 안에 「마감」으로 바뀝니다. 강좌 하나만 멈출 때는 「강제마감」을 쓰십시오.

꿈키움 화면의 안내 문구

꿈키움 학생 화면 위쪽의 일정 안내 문구는 화면 파일에 직접 적혀 있어 기간을 바꿔도 따라 바뀌지 않습니다. 꿈키움 일정을 바꿀 때는 개발 담당에게 문구 수정을 함께 요청하십시오.

학생 화면 상태

상태(phase)학생 화면
before_open공개 전: 「강좌 목록은 ○월 ○일에 공개합니다」 / 공개 후: 강좌 목록과 「강좌 미리 보기 기간입니다. 신청 시작까지 ⏳」
open11차 신청 가능, 마감까지 카운트다운
between1차 마감 후 2차 시작 전, 「2차 신청 시작까지」 카운트다운
open22차 신청 가능
closed「신청이 마감되었습니다」
not_configured적용되는 기간이 없음. 기본 기간을 넣어야 함

SQL로 한꺼번에 확인하기

Supabase 대시보드 → SQL Editor → New query에 붙여 넣고 Run을 누릅니다. 지역이 「(기본 기간)」인 줄이 기본 기간입니다. 기간을 SQL로 바꾸지는 마십시오.

SELECT program,
       coalesce(region, '(기본 기간)') AS 지역,
       preview_at AT TIME ZONE 'Asia/Seoul' AS "강좌 공개",
       open_at    AT TIME ZONE 'Asia/Seoul' AS "1차 시작",
       close1_at  AT TIME ZONE 'Asia/Seoul' AS "1차 마감",
       open2_at   AT TIME ZONE 'Asia/Seoul' AS "2차 시작",
       close2_at  AT TIME ZONE 'Asia/Seoul' AS "2차 마감"
  FROM settings ORDER BY program, region NULLS FIRST;

6. 신청 기간 중 관리

강제마감 · 정원 수정 · 명단 삭제 방법은 지역청 매뉴얼 9장과 같습니다. 도교육청 계정은 모든 프로그램의 강좌에 할 수 있습니다.

문의대응
취소비번을 잊었어요본인 확인 후 명단에서 그 신청을 삭제하고, 다시 신청하도록 안내합니다.
지역연계 2번째 강좌가 안 돼요지역연계도 1인 1강좌이므로 정상입니다.
학년 때문에 신청이 안 돼요학년 제한 강좌는 운영 학년도 기준 학년을 현재 학년으로 환산합니다. 강좌의 시작일과 「수강 대상」을 확인합니다.
마감 뒤에 취소하고 싶어요학생이 직접 취소할 수 없습니다. 본인 확인 후 명단에서 삭제합니다.
다른 지역과 신청 기간이 달라요그 지원청에 지역 기간이 들어 있는 것입니다. 「신청 기간」 창에서 확인합니다.
학교 이름이 검색되지 않아요학교 목록은 화면 파일에 있습니다. 개발 담당에게 추가를 요청합니다.

7. 명단 내려받기

  • 전체 엑셀: 지금 보고 있는 탭과 관계없이 로그인한 계정이 볼 수 있는 모든 신청자를 내려받습니다. 마스터 계정이면 모든 프로그램이 들어갑니다.
  • 강좌별 엑셀: 그 강좌 신청자만 내려받습니다.
개인정보

명단에는 학생 이름과 연락처가 들어 있습니다. 업무용 PC에만 저장하고, 메일로 보낼 때는 암호를 걸어 보내십시오. 보관 기간이 지나면 파일을 삭제하십시오.

8. 계정 관리와 문제 해결

새 담당자 계정 (가입 신청 → 승인)

  1. 새 담당자(또는 도교육청 담당자가 대신)가 로그인 창 아래 「지역청/기관 담당자 가입 신청」을 누릅니다.
  2. 이메일 → 비밀번호(8자 이상) → 이름 → 역할(지역청 region, 기관 org) → 소관 이름을 차례로 입력합니다. 소관은 지역청이면 「천안교육지원청」처럼 전체 이름, 기관이면 강좌의 「운영 기관」과 같은 이름입니다.
  3. 마스터 계정으로 가입 승인을 눌러 이름 · 역할 · 소관을 확인하고 승인합니다.

비밀번호 초기화 (SQL)

UPDATE auth.users
   SET encrypted_password = extensions.crypt('새비밀번호', extensions.gen_salt('bf')),
       updated_at = now()
 WHERE email = 'cheonan@onmadang.kr';      -- 대상 아이디

결과가 「1 row」이면 바뀐 것이고, 「0 rows」이면 이메일을 잘못 적은 것입니다.

계정 사용 중지·다시 사용 (SQL)

-- 중지
UPDATE staff_profiles SET status = 'rejected'
 WHERE id = (SELECT id FROM auth.users WHERE email = 'cheonan@onmadang.kr');
-- 다시 사용
UPDATE staff_profiles SET status = 'approved'
 WHERE id = (SELECT id FROM auth.users WHERE email = 'cheonan@onmadang.kr');

마스터 계정 추가 (후임자 인계)

후임자가 가입 신청(역할 region, 소관은 아무 값)을 한 뒤, 승인하지 말고 아래를 실행합니다. 후임자 화면에 「가입 승인」 단추가 보이면 완료이며, 전임자 계정은 중지합니다.

UPDATE staff_profiles
   SET role = 'province', scope_value = NULL, status = 'approved'
 WHERE id = (SELECT id FROM auth.users WHERE email = '후임자이메일');

문제 해결

증상확인할 것
로그인이 안 됨① 오타 ② 계정 승인 상태(「가입 승인」 창) ③ 비밀번호 초기화
강좌가 학생 화면에 안 보임① 강좌 공개 전인지 ② 주소의 program= 값 ③ 「신청 가능(목록 노출)」 체크 ④ 지역연계는 강좌 「지역」 값과 학생이 고른 지역이 같은지
지역청 담당자에게 강좌가 안 보임강좌 「지역」 값이 담당자 소관과 글자까지 같은지 확인하고 「수정」으로 고칩니다.
학생 화면이 「신청 기간이 아님」「신청 기간」 창에서 기본 기간과 그 지역 줄을 확인합니다.
신청/정원 숫자가 명단과 다름아래 보정 SQL을 실행합니다.
강좌가 삭제되지 않음확정 신청이나 선점 중인 좌석이 있는 강좌입니다. 신청을 지운 뒤 삭제하거나 강제마감을 씁니다.
 
UPDATE courses SET enrolled_count = (
  SELECT COUNT(*) FROM enrollments
   WHERE enrollments.course_code = courses.code
     AND enrollments.status IN ('active', 'pending')
);

9. 회차 종료 후 정리 (전체 초기화)

한 회차가 끝나 다음 회차 강좌를 새로 받기 전에, 그 프로그램의 강좌와 신청자를 모두 지웁니다. 프로그램 정보와 신청 기간 설정은 남습니다.

  1. 「전체 엑셀」로 명단을 내려받아 보관했는지 먼저 확인합니다.
  2. 지울 프로그램 탭을 누르고, 빨간 「위험 구역」의 이 프로그램 전체 초기화를 누릅니다.
  3. 입력 창에 프로그램 이름을 정확히 입력하고(예: 지역연계 공동교육과정) 마지막 확인 창에서 확인합니다.
되돌릴 수 없습니다

지역연계에는 이미 실제 강좌가 등록되어 있습니다. 남은 데모 강좌(JR26DEMO1)는 전체 초기화가 아니라 강좌 표의 「삭제」로 지우십시오.

10. Supabase 요금제

신청 기간에는 동시 접속이 많아 Pro로 운영하고, 평소에는 Free로 둡니다. 대시보드 → 조직 설정(Organization) → Billing에서 바꿉니다. Free 요금제는 오래 접속이 없으면 프로젝트가 일시 중지될 수 있으니(「Paused」 → 「Restore」), 강좌 공개 전에 반드시 확인하십시오.

11. 하지 말아야 할 것

  • SQL 편집기에서 이 문서에 없는 문(특히 DELETE · DROP · TRUNCATE)을 실행하지 마십시오.
  • settings 표(신청 기간)를 SQL이나 Table Editor로 직접 고치지 마십시오. 1판 매뉴얼의 기간 설정 SQL(INSERT … ON CONFLICT)은 이제 오류가 납니다.
  • 신청 기간 중에 「전체 초기화」를 누르지 마십시오.
  • 공유 비밀번호와 계정 비밀번호를 공문 · 단체 메신저에 적지 마십시오.
  • 강좌의 「지역」을 약칭(예: 천안)으로 적지 마십시오.
  • Table Editor에서 courses · enrollments 표를 직접 고치지 마십시오. 신청 인원 숫자가 어긋납니다.
