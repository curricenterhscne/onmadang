## 설계 (확정)
- **Supabase 프로젝트**: 수강신청과 같은 `yhrgvnttjlitukrxdfdo`(Pro). 게시판 표는 `board_` 접두어로 따로 둔다. 학생 개인정보는 없다.
- **표 `board_posts`**: id(기존 GitHub 이슈 번호 유지), board(`notice`|`resource`), title, body(마크다운), category, is_important, attachments(jsonb `[{name,path,size}]`), author, created_at, updated_at, deleted_at(지운 글 숨김·복구용).
  - RLS: 지워지지 않은 글은 누구나 읽는다. 쓰기 정책은 없다(Edge Function의 service role만 쓴다).
- **표 `board_settings`**: 담당자 암호 해시. **표 `board_log`**: 로그인·쓰기 기록(관리용). 둘 다 RLS로 막는다.
- **저장소 버킷 `board-files`**: 공개 읽기, 파일당 50MB. 키는 `YYYYMM/uuid.확장자`, 원래 이름은 attachments.name에 둔다. 다운로드는 `?download=원래이름`.
- **Edge Function `board-admin`** (`--no-verify-jwt`): 암호를 확인하고 역할(master/editor)을 정한다.
  - action: login, create, update, delete, restore, list_deleted, upload_url, set_editor_password, log
  - 실패 10회/15분이면 그 IP를 막는다.
  - 마스터 암호는 함수 비밀값 `BOARD_MASTER_PASSWORD`(담당자가 대시보드에서 넣는다).
- **화면**:
  - `board/index.html` = 알림·소통 마당 첫 화면(시안 sub04_00)
  - `board/notices.html` = 공지 목록(새 주소). `board/notice.html?id=` 상세는 주소 유지
  - `board/resources.html`·`board/resource-view.html?id=` 주소 유지
  - `board/admin/` = 담당자 글쓰기 화면(noindex)
  - 공용 스크립트 `board/js/board.js`. 본문은 marked + DOMPurify로 정화한다.
  - 홈 알림·소통 마당 목록도 Supabase에서 읽는다.
- **기존 글 옮기기**: GitHub 이슈(공지 9, 자료 2, closed 테스트 제외) → `supabase/sql/board_import_github.sql`. 번호를 그대로 쓴다.
