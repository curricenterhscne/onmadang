# 학생 자료 공개 기준

이 저장소와 사이트는 누구나 볼 수 있다. `noindex`, 링크 비노출, 페이지 소스에 숨긴 자료는 보호 수단이 아니다.
삭제한 파일도 커밋 이력에서 열린다. 한 번 커밋한 자료는 공개된 것으로 본다.

## 원칙

1. 학생 명단, 학번, 연락처, 성적·이수 결과, 스캔본의 원본은 저장소에 넣지 않는다. 이름을 일부 가려도 강좌·이수 여부와 묶이면 학생 자료로 본다.
2. 학생별 결과는 학교 배부를 먼저 검토한다. 웹 조회가 꼭 필요할 때만 아래 도구로 만든다.
3. 학생 자료를 다루는 페이지와 데이터는 공개 전에 `register.json`에 등록하고 종료일을 정한다.
4. 종료일이 되면 내리고, 내린 뒤 원본 보관 여부를 담당자가 판단한다.

## 조회 페이지 만들기

```text
node tools/lookup/build.js <명단.csv> <설정.json> <출력.html>
```

- 명단 CSV의 첫 네 열은 `학교,학년,학번,이름`이고, 나머지 열은 결과 항목이다. 저장소 밖에 둔다.
- 설정 JSON에는 `title`, `lede`, `note`, `end`(종료일), `base`(공통 파일까지의 상대경로)를 적는다.
- 결과값은 학교·학년·학번·이름으로 만든 키로 암호화된다.
- **한계:** 학번과 이름을 아는 사람은 그 학생의 결과를 볼 수 있다. 민감한 자료는 이 방식으로 공개하지 않는다.
- 종료일이 지나면 화면은 닫히지만 파일은 남는다. 파일 교체까지 해야 끝난다.

## 자동 검사

| 시점 | 내용 |
|---|---|
| 커밋 전 | `.githooks/pre-commit`이 올리는 파일을 검사한다. 저장소를 새로 받으면 `git config core.hooksPath .githooks`를 한 번 실행한다 |
| 푸시 후 | GitHub Actions가 추적 파일 전체를 검사한다. 실패하면 GitHub가 메일로 알린다 |
| 매주 월요일 | GitHub Actions가 `register.json`의 종료일을 검사한다 |

검사가 잡지 못하는 자료도 있다. 스캔 이미지의 내용은 읽지 못하므로 파일 경로로만 판단한다. 검사를 통과해도 원칙 1은 그대로 적용한다.

자료가 아닌 파일이 걸리면 `tools/privacy_allow.txt`에 경로와 이유를 적는다.

## 자료를 잘못 올렸을 때

1. 사이트와 브랜치의 파일을 먼저 내린다.
2. 개인정보 담당 부서에 알린다.
3. 커밋 이력에서 지운다. 해시가 모두 바뀌므로 진행 중인 브랜치를 함께 정리한다.
4. GitHub 지원팀에 캐시된 커밋 삭제를 요청한다.
